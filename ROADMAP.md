# Paseo État-major roadmap

**Proposed · 28 November 2026**

Help maintainers and reviewers of agent-assisted projects answer three questions from a task in Paseo: why are we doing it, what does the delivery evidence show, and what still needs a human decision? Start with one Git-backed project and one trace from research through decision, feature, task, and evidence. État-major owns the records and derivation rules. Paseo provides the review surface and owns session access. [État-major traceability model](https://github.com/bearyjd/etat-major/blob/main/docs/TRACEABILITY.md)

## Baseline

Planning, recorded PR and release inputs, and Discover are merged. A release recording currently shows source status and supplies no shipped proof. Discover displays decisions and research with provenance and citation status. GitHub had no published tag or release at the time of the Discover merge. Live-host, web, and phone acceptance remains open. [Changelog](https://github.com/bearyjd/paseo-etat-major/blob/main/CHANGELOG.md) · [Manual acceptance](https://github.com/bearyjd/paseo-etat-major/blob/main/README.md#manual-acceptance) · [Discover PR](https://github.com/bearyjd/paseo-etat-major/pull/8)

## Delivery milestones

| Priority | Proposed increment | Acceptance |
| --- | --- | --- |
| **Now · 1. Prove the install and ship Discover** | Pin the supported Paseo and exporter versions. Run Planning and Discover acceptance on an isolated host with one real project at the merged revision, then publish and reinstall the verified release tag. | Record host, web, phone, plugin, and exporter versions. Load both views and compare them to CLI output. Exercise refresh, concurrent export handling, older-exporter messaging, and reinstall. Confirm rejected and unsourced records render correctly, then record the results. |
| **Next · 2. Connect the first trace** | Link a Planning task to its feature, decision, and cited finding, with reverse navigation from Discover. Use stable État-major IDs and display the relevant evidence rungs and human acceptance. Start with Planning and Discover export fixtures. Propose a bounded upstream export addition if the current contracts omit a required relation. | On web and phone, a reviewer can follow one real feature in both directions. Cover a rejected alternative, missing citation, and merged-but-unaccepted task. Missing, omitted, and stale data are visible, and absent proof reads `unverified`. |
| **Next · 3. Show what a milestone needs** | Add a compact Now/Next/Later view with milestones, blockers, and open acceptance items. Reuse upstream milestone and dependency semantics. Add recording timestamps and distinct missing, invalid, and stale source states where the upstream contract supplies them. [Upstream planning and progress phases](https://github.com/bearyjd/etat-major/blob/main/docs/VISUALIZATION-ROADMAP.md#phase-4-planning-visualization) | A reviewer can pick the next milestone, name the dependency holding it up, and inspect the remaining evidence from phone or web. Stale or partial recordings cannot make a milestone appear verified. |
| **Later · 4. Connect code and existing sessions** | If the trace pilot shows demand, add a feature-to-component inspector using versioned upstream recordings. Separately validate an explicit open-existing-session action with the supported Paseo SDK and host-side authorization. [Upstream Understand MVP](https://github.com/bearyjd/etat-major/blob/main/docs/UNDERSTAND-MVP.md) | A matching recording shows the component and revision, while stale or missing recordings explain the gap. A session action opens only an authorized existing session and can return to the original task. |

The plugin remains a read-only consumer of bounded, versioned exports. Work on live evidence collection or release-tag correlation starts with an upstream contract and a concrete pilot need. Issue synchronization, workspace writes, agent scheduling, and transcript capture are outside this roadmap. ## Pilot and decision criteria

Use one real project with an approved decision, a rejected alternative, and tasks with different evidence states. Ask a maintainer and a second reviewer to find the rationale, show the strongest available proof, and name the unresolved acceptance item. Time the same exercise in their current workflow and in the plugin. Use different but comparable tasks for the second pass to reduce recall bias.

Proposed gate for expanding beyond the trace: both reviewers answer all three questions correctly without assistance, the plugin reduces median time by at least 30%, and neither reviewer mistakes missing evidence or a merged PR for human acceptance. Record times and misreads locally. If the pilot misses the gate, improve navigation and evidence labels before adding more views.
